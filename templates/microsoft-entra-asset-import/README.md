# Microsoft Entra Asset Import

Imports Microsoft Entra ID (Azure AD) users and groups into Jira Assets on a daily schedule.

The template installs three flows that each create/refresh an external import source in Jira Assets and populate it from the Microsoft Graph API:

- `Microsoft Entra User Asset Import`: imports users (`displayName`, `givenName`, `jobTitle`, `mail`, `mobilePhone`, `officeLocation`, `preferredLanguage`, `surname`, `userPrincipalName`, `id`) into a `Users` object type, and offices into an `Office Location` object type.
- `Microsoft Entra Group Asset Import`: imports groups (`id`, `displayName`, `description`, `mail`, `mailEnabled`, `mailNickname`, `uniqueName`, `createdDateTime`, `deletedDateTime`) into a `Groups` object type.
- `Microsoft Entra User-Group Asset Import`: for every user, fetches their Entra group memberships and links the existing `Users` objects to the existing `Groups` objects via a `groups` reference attribute.

All three flows run on the same schedule (`0 9 * * *`) and are disabled by default. Enable the user and group import flows first; the user-group relation flow expects both `Users` and `Groups` objects to already exist in the target schema (matched by `displayName`), so run/enable it after the first two have completed at least once.

## Required Customer Configuration

Hard-coded values that must be reviewed before enabling the flows:

| Value in template                                                                        | Where                                              | Customer action                                                                                                     |
| ----------------------------------------------------------------------------------------- | --------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `{tenant}` in the `oauth2-microsoft-entra` credential's authorize/token URLs               | `manifest.json`                                    | Replace with the customer's Entra tenant ID (or `common`/`organizations` for multi-tenant apps) when creating the credential. |
| `711ab3b8-1b00-4ccf-ad20-55e3946ebdd8`                                                     | `microsoft_entra_user_asset_import.json`           | Replace with the Jira Assets import source ID for that customer's user import, or let it be created fresh if the import source doesn't exist yet. |
| `5a4fb8eb-03fd-4d4e-a709-b7f1b7a0f1fd`                                                     | `microsoft_entra_group_asset_import.json`          | Same as above, for the group import source.                                                                          |
| `010eefa7-d640-45bd-b3ac-41aa5e019665`                                                     | `microsoft_entra_user_group_asset_import.json`     | Same as above, for the user-group relation import source.                                                            |
| `Microsoft` (`assetSchema` flow variable)                                                  | All three flow JSON files                          | Replace with the name of the target object schema in Jira Assets.                                                    |

Each `importSourceId` is generated by Jira Assets the first time an external import source is created for a schema. If the customer is starting fresh, these values can be left as-is on first run and the import will create a new source; if they already have an existing import source for these objects, replace the ID so the flow updates it instead of creating a duplicate.

## Credentials

- `oauth2-microsoft-entra` (OAuth2): Microsoft Entra app registration used to call Microsoft Graph. Requires the delegated scopes `offline_access User.Read User.Read.All Group.Read.All`. Grant admin consent for `User.Read.All` and `Group.Read.All` in the customer's tenant before authorizing.
- `token-microsoft-entra-user-asset-import-token` (Token): Jira Assets API token used by the user import flow to manage its import source.
- `token-microsoft-entra-group-asset-import-token` (Token): Jira Assets API token used by the group import flow.
- `token-microsoft-entra-group-asset-import-token-2` (Token): Jira Assets API token used by the user-group relation flow.

The three Jira Assets tokens can point at the same API credential; they are kept separate so each flow's import source calls can be swapped independently if needed.

## Notes

- Each flow cancels its own import if a previous run is still `RUNNING` when the next scheduled run starts, to avoid stuck imports blocking future syncs.
- Microsoft Graph responses are paginated using `@odata.nextLink`; the flows follow this automatically via `USER_PAGE_URL`.
