# Zoho Asset Import

Imports Zoho Mobile Device Management (MDM) users, groups, and devices into Jira Assets on a daily schedule.

The template installs three flows that each create or refresh an external import source in Jira Assets and populate it from the Zoho MDM API:

- `Zoho User Asset Import`: imports managed users (`user_id`, `name`, `email_address`, `phone_number`, `domain`) into a `Users` object type.
- `Zoho Group Asset Import`: imports MDM groups (`group_id`, `name`, `group_type`, `domain`) into a `Groups` object type.
- `Zoho Device Asset Import`: imports managed devices (`device_id`, `device_name`, `product_name`, `model`, `serial_number`, `imei`, `udid`, `platform_type`, `platform_type_id`, `os_version`, `owned_by`, `is_lost_mode_enabled`, `is_removed`) into a `Devices` object type and links assigned users when matching `Users` objects exist.

All three flows run on the same schedule (`0 9 * * *`) and are disabled by default. Enable the user and group import flows first; the device import flow can link devices to users after the `Users` objects have been imported at least once.

## Required Customer Configuration

Hard-coded values that must be reviewed before enabling the flows:

| Value in template | Where | Customer action |
| --- | --- | --- |
| `0f3850a6-d813-4de4-90c9-4e703a4c8d6a` | `zoho_user_asset_import.json` | Replace with the Jira Assets import source ID for that customer's user import, or let it be created fresh if the import source does not exist yet. |
| `1cc93e4a-72f6-4244-a98f-5d48d7c2f4ec` | `zoho_group_asset_import.json` | Same as above, for the group import source. |
| `9340bc44-b37f-4a58-a823-fb4d92601636` | `zoho_device_asset_import.json` | Same as above, for the device import source. |
| `Zoho` (`assetSchema` flow variable) | All three flow JSON files | Replace with the name of the target object schema in Jira Assets. |

Each `importSourceId` is generated by Jira Assets the first time an external import source is created for a schema. If the customer is starting fresh, these values can be left as-is on first run and the import will create a new source; if they already have an existing import source for these objects, replace the ID so the flow updates it instead of creating a duplicate.

## Credentials

- `oauth2-zoho-mdm` (OAuth2): Zoho MDM credential used to call the ManageEngine MDM API. Requires the read scopes for managed users, groups, and inventory.
- `token-zoho-user-asset-import-token` (Token): Jira Assets API token used by the user import flow to manage its import source.
- `token-zoho-group-asset-import-token` (Token): Jira Assets API token used by the group import flow.
- `token-zoho-device-asset-import-token` (Token): Jira Assets API token used by the device import flow.

The three Jira Assets tokens can point at the same API credential; they are kept separate so each flow's import source calls can be swapped independently if needed.

## Notes

- Each flow cancels its own import if a previous run is still `RUNNING` when the next scheduled run starts, to avoid stuck imports blocking future syncs.
- Zoho MDM list responses are paginated using `paging.next`; the flows follow this automatically through `PAGING_NEXT`.
- The device flow flattens Zoho's nested `user` and `summary` response objects before submitting data to Jira Assets.
